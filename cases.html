Use cases · Workflows

Seven jobs for Jev, run on real Hermes data

Each case is a decision your workflows already make, or could make, with an agent step today. Every number below comes from live Jev calls against real NousResearch/hermes-agent issues, PRs and comments, scored against the labels maintainers actually applied.

926 live calls · $0.046 total · 184 ms median per call · model typesafe/jev-1.14 via OpenRouter. Code and raw results are in cases/.
01 · Agent step → Gate

Did the step actually work?

Every gate starts from a verdict on the step before it. When an agent step doesn't return an explicit verdict, today's runner searches its reply for PASS, or a reply that starts with YES. Here are 10 step summaries, each asked as one Noul: "The step achieved its goal and the work is ready to move on."

The substring rule gets 6 of 10 wrong; Jev at 0.5 gets 0 wrong. The substring misses aren't edge cases: "should NOT PASS", "PASSED the type check; the runtime still crashes" and "Yes, I looked at it. 02 · Webhook (PR opened) → Gate

Catalog and docs are clean enough to automate today. For example, a catalog-only PR could skip the full review agent and go straight to the catalog checks.

Security behaves like a smoke detector. It sends 26 PRs to a human (2 of them labelled security). Its "wrong" yes answers are worth reading:

  • #139195 feat(providers): let provider plugins claim tenant-scoped endpoint hosts (0.93)
  • #139191 fix(whatsapp): handle locked session dir on re-pair and reject empty creds in preflight (0.85)
  • #139063 fix(gateway): preserve secondary local session policy (0.80)
  • #139010 fix(agent): preserve custom provider headers for auto titles (0.85)
  • #138958 feat(plugin-catalog): add hermes-xai (Grok Voice for Desktop + read-only xAI Collections search) (0.82)

Most of these handle credentials or tokens and simply never got a security label. That makes them misses in the labels, not mistakes by Jev. For a security arm, a false alarm costs a minute of a reviewer's time; a missed real one costs far more. Wire this arm to a human, never to auto-merge.

03 · Webhook (PR opened) → Agent (comment)

Spot competing PRs

The repo has four known pairs of PRs that fix the same thing. Maintainers or triage bots flagged them in comments like "closing in favour of…". I mixed those 8 PRs with 30 random others and a near-miss pair, then asked each PR one question about every other PR in the pool: 39 Nouls in a single request, with no embeddings, vector store or pairwise prompts.

questions = {
  str(other.number): {"type": "noul", "instructions": {
      "other_pull_request": {title, description, files},
      "question": "This other pull request fixes the same underlying problem…"}}
  for other in open_prs }

Perfect separation. The lowest real duplicate scored 0.82; the highest unrelated pair scored 0.16. The near miss is the impressive one: two "retry on update" PRs from the same afternoon, with almost the same titles, that fix different code paths. Jev put them at 0.12. A title-similarity bot would have flagged them.

Cost: 10 calls, $0.0077, about 283 ms each, for every pair in a 40-PR pool. In a workflow, a new PR asks one question per open PR in the same component. When the score is above 0.8, an agent step drafts the "possible duplicate of…" comment for a human to post.

04 · Webhook (issue opened) → Gate → Agent per component

Route issues to a component

One Choice over the repo's 11 comp/* labels, using the label descriptions from GitHub as the options. A pick counts as right if it matches any of the issue's maintainer-applied comp/ labels. That's 150 issues, and 89% were right overall, but the overall number isn't the useful part. The useful part is what the confidence tells you:

ConfidenceIssuesRight
0.9 or higher9192%
0.6 to 0.94388%
below 0.61669%

A gate that auto-routes at 0.9 or higher handles 61% of issues at 92% accuracy and sends the rest to the triage agent. Its confident misses are mostly reasonable disagreements:

  • #138923 Public subagent lifecycle re-truncates native summaries and drops spill recovery metadata: picked comp/agent at 0.99; maintainers said comp/plugins
  • #138893 npm vulnerabilities flagged by hermes doctor — missing overrides for minimatch, jsdom, undici, vitest, yaml: picked comp/cli at 0.99; maintainers said comp/tui, comp/dashboard
  • #139121 [Bug]: Streaming STT resampler adds samples when 44.1 kHz audio arrives in chunks: picked comp/tools at 0.97; maintainers said comp/desktop
  • #138793 Telegram: messages held across a disconnect are replayed out of order: picked comp/gateway at 0.97; maintainers said comp/plugins

Tune on one set, score on another

Many misses are messaging adapters, which this repo files under comp/plugins. Rewriting the option descriptions to say so looks like an obvious fix. On 150 held-out issues, though, the original descriptions score 88% (93% at 0.9 or higher), and the "improved" ones score 85% (90%). The rewrite was fitted to the misses it was written from. Keep a held-out set, and don't tune questions on the examples you score them with.

05 · Human step (reply from Telegram/Slack/Discord)

Read an approval reply

The Human step parks until someone answers from a chat. A Choice turns the free-text reply into something the run can act on. The conditional and question options matter most: they keep "yes but fix the typo first" from counting as a yes.

07 · The negative result

Where it falls short: priority

Score was asked to place each bug on the repo's P3 to P0 rubric. On 120 labeled bugs it hit the exact label only 40% of the time, and its average score barely separates P3 from P2:

LabelBugsMean score (0 = P3, 3 = P0)
P3361.55
P2791.58
P152.11

For ranking, though, it's useful: a random P1 outscores a random non-P1 0.79 of the time (0.5 would be chance). The top of the list is the right kind of bug:

  • #139085 [Bug]: a gateway worker under a Python 3.14 runtime inherits a legacy hermes-agent/venv (cp311) (P2, 2.98)
  • #138914 session.list crash-loops when a live session's DB row is gone (TypeError in session_authority._h (P2, 2.97)
  • #138794 [Bug]: TUI session list never loads (TypeError in session_authority._handle) after `hermes sessi (P2, 2.94)
  • #139062 execute_code: a nested tool call outlives its cell and applies a protected-file write after the (P2, 2.87)
  • #138939 Kanban dispatcher kills worker PID from DB without verifying process identity (PID reuse can hit (P3, 2.85)
  • #139132 Windows: interrupted source-update auto-repair loops on every launch (sync-stage failures bypass (P2, 2.83)

So use it to sort the queue, not to set the label. P2 versus P3 here mostly depends on things that aren't in the issue text: how many people are affected, what's shipping this week, which maintainer picked it up. Jev can only judge what's in the state you send it, and here the state doesn't contain the answer. Splitting the rubric into six separate Noul questions combined with weights (TypeSafe's recommended "atomic questions" approach) didn't help either: 0.80 versus 0.79.

Build order

  1. Step verdicts (01). This fixes a real bug in the runner, and every gate benefits.
  2. Competing-PR detection (03) on PR intake. It separated the pairs perfectly here, and it saves maintainers the most time.
  3. Approval replies (05) for the Human step. Without it, a reply from chat can't drive the run at all.
